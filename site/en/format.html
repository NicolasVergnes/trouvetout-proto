Data format

Your data must be readable without the app, today as in ten years. This is how an export is made.

Format version 1. A v1 export imports into every later version: the format only grows by adding fields or event types, never by renaming or removing. A reader ignores what it does not know. The full reference, with the SQLite schema, is in French: docs/format-export.md; the event table is on the French page.

The ZIP export

Settings → Export creates trouvetout-export-YYYYMMDD-HHMMSS.zip (UTC), which you share wherever you like. It is not encrypted.

manifest.json     { "formatVersion": 1, "appVersion": "…", "schemaVersion": 1, "exportedAt": <ms UTC>,
                    "deviceId": "…", "counts": { "events": n, "items": n, "places": n, "containers": n, "photos": n } }
events.jsonl      the full journal, one JSON event per line, sorted by (at, deviceId, id)
snapshot.json     the current state at a glance: items, places, containers, locations, photos, reminders
photos/<id>.jpg   the photos, recompressed (long side ≤ 2048 px), without their original metadata

For a quick look, open snapshot.json. For the whole history, events.jsonl (JSON Lines: one object per line). snapshot.json is never imported back: it is recomputed from the journal.

The event journal

Every action is an immutable event, dated and signed by the device; nothing is ever overwritten. Each line has id (ULID), at (UTC milliseconds), deviceId (random identity of the installation, never sent, renewed after a total wipe; like any ULID, its first 10 characters give the date of the first launch), actor ("me"), type, payload (the fields of that type), source (VOICE, TEXT, PHOTO, WIDGET, IMPORT, SYSTEM) and rawInput (the sentence said or typed, as is). Event types cover objects (created, updated, stored, moved, taken, returned, lent, archived, deleted, restored), places (created, renamed, merged, deleted), containers (created, moved with their contents, deleted), photos (attached, detached) and reminders (set, done).

What an export contains

Everything, sensitive objects included, and only what you entered or what follows from it: names, descriptions, tags, places and their aliases, containers, the full sentence said or typed, the names of people you lent things to, the dates of your actions, your re-encoded photos and the installation's random identifier (which dates your first launch). Nothing comes from a sensor, an account, a contact or a system identifier. Phone settings (lock, preferences, trial date, purchase state) are not in it.

The encrypted backup (.ttbk)

  • 41-byte header: TTBK, version (1 byte, 1), block size (4 bytes, big-endian, 1048576), random salt (32 bytes).
  • Recovery key: 28 Crockford base-32 characters (dashes ignored; O reads 0, I and L read 1): 16 key bytes, 1 check byte (first byte of the key's SHA-256), 4 zero bits.
  • File key: HKDF-SHA-256 (RFC 5869) of the recovery key, header salt, info trouvetout-backup-v1, 32 bytes.
  • Blocks: the archive cut into 1 MiB blocks, each sealed with AES-256-GCM (ciphertext then 16-byte tag). 12-byte nonce: 3 zero bytes, block number from 0 (8 bytes, big-endian), then 1 for the last block and 0 otherwise. Additional data: the whole header.

Altering, reordering, truncating or extending the file makes it impossible to open.
